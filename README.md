# Bugboard

内网用的多项目报障台账。人在网页上提报、接单、确认；测试 Agent 和修复 Agent 用同一套状态机走 REST / MCP。数据在本机 SQLite，附件存在本地磁盘。

确认权只在原报障人。没有自助注册，没有邮件或即时通知，刷新列表就能看到最新状态。

## 使用手册

### 第一次打开

空库会进入首装页。填一个用户名和至少 6 位的密码，这个账号就是超级管理员，并直接进入项目列表。之后只有管理员能开户，登录页没有注册入口。

右上角头像菜单可以改自己的密码，或退出。改密码需要当前密码，新密码至少 6 位。

### 三种角色

| 角色 | 能看到什么 | 主要做什么 |
|------|------------|------------|
| 用户 | 被分配进去的项目 | 提报、补充材料、确认修复、打回、对「不属实」提异议或认可 |
| 管理员 | 全部项目 | 开户、建项目、分成员、接单、写修复说明、标不属实、管 API Key |
| 超级管理员 | 全部项目 | 管理员的全部能力，另外可以任命超级管理员，删除项目和报障 |

管理员默认能进所有项目，不必再加为成员。普通用户没被加进任何项目时，项目列表是空的，需要管理员在项目的「成员」页分配。

超级管理员可以改、禁用、删除其他超级管理员。普通管理员不能动超级管理员账号，也不能删除自己正在登录的账号。禁用后的用户不能再登录。

### 界面怎么走

登录后落在 **项目** 列表。列表上方是 **待我处理**：只列出这个账号现在要处理的单，按项目分组，点一条进入该单。某个项目没有要你处理的单时，这里不显示该项目。没有待办时，这里只有一句「现在没有需要你处理的报障」。

每张项目卡片上的数字仍是项目层面的数量：

- 管理员看到 **待处理 / 待补充 / 待确认**（整个项目）。
- 用户看到 **待补充 / 待确认**（只计自己提交的）。

点进项目后默认是报障列表。顶部可以切到别的项目。项目内有三个分区：

- **报障**：筛选、排序、新建。
- **汇总**：总数和各状态数量，以及最近 7 / 30 / 90 天的新建与流入趋势。
- **成员**：仅管理员可见。勾选用户加入项目，或把成员移出。

报障列表可以按状态、优先级、提交人筛选，也可以搜标题或报障编号。表头可以排序。编号形如 `SOC251106001`：项目缩写 + 上海时区日期 + 当天序号。

点开一条报障，左侧是 **下一步**（只显示当前身份此刻能做的动作），右侧是正文、附件和时间线。时间线上的每次流转都带着操作人和说明。

### 提一张报障

在项目的报障页点 **新建报障**。

1. 标题用一句话写清现象。
2. 正文写环境、复现步骤、期望和实际结果。支持 Markdown：二级标题、空行分段、有序列表。
3. 选优先级。不选就是 P2。
   - **P1**：核心流程不可用、崩溃、错误结果、数据风险。
   - **P2**：能用，但行为不对或不稳定。
   - **P3**：不挡使用，偏界面、文案、交互。
4. 需要的话再加附件，然后提交。提交后会打开这张单的详情。

附件可以拖进来、从剪贴板粘贴图片，也可以用麦克风录音。新建时可以圈一张图并说一句，或录一段走查：走查会先拆成草稿，看完才变成多张报障。单文件不超过 50MB，一张单最多 20 个。支持 png、jpg、gif、webp、mp4、webm、mov、pdf、docx、xlsx、txt、md、zip，以及 mp3、wav、ogg、m4a。

一条报障只写一个现象。这是现有功能坏了，不是要一个现在没有的能力。要加新能力时，先和项目资料里的产品经理确认；修复侧看到「已经和产品经理沟通确认」一类说法，才会按新需求改。

### 状态怎么走

```text
待处理 ──接单──▶ 修复中 ──提交修复说明──▶ 待确认 ──确认已修复──▶ 已确认
   │               │                         │
   │               │                         └──仍有问题──▶ 待处理
   │               │
   ├──标为不属实──▶ 不属实 ──提出异议 / 撤回不属实──▶ 待处理
   │                  └──认可不属实──▶ 已认可
   │
   └──要求补充──▶ 待补充 ──补充材料──▶ 待处理
```

待确认时，管理员还可以 **撤回修复提交**，单回到修复中。

| 动作 | 谁来做 | 从 | 到 | 说明 |
|------|--------|----|----|------|
| 接单（开始修复） | 管理员 | 待处理 | 修复中 | 可选 |
| 提交修复说明 | 管理员 | 修复中 | 待确认 | 必填。建议写成「原来的问题 / 现在的表现 / 请这样重测」 |
| 确认已修复 | 原报障人 | 待确认 | 已确认 | 可选。已确认是终态 |
| 仍有问题 | 原报障人 | 待确认 | 待处理 | 必填，写仍失败的步骤 |
| 标为不属实 | 管理员 | 待处理、修复中 | 不属实 | 必填，写实际看到了什么、为什么对不上 |
| 提出异议 | 原报障人 | 不属实 | 待处理 | 必填 |
| 认可不属实 | 原报障人 | 不属实 | 已认可 | 可选。已认可是终态，不能再异议或撤回 |
| 撤回不属实 | 管理员 | 不属实 | 待处理 | 必填，写上次判错的地方 |
| 要求补充 | 管理员 | 待处理、修复中 | 待补充 | 必填。缺的是只有报障人能提供的材料 |
| 补充材料 | 原报障人 | 待补充 | 待处理 | 必填，可同时附截图或记录 |
| 撤回修复提交 | 管理员 | 待确认 | 修复中 | 必填 |

「原报障人」是创建这张单的那个账号或那把 API Key。管理员代提的单，确认、打回、异议、认可不属实和补充材料也只有那个管理员能做。别人打开详情时，下一步是空的，只能看时间线。

管理员可以在详情里改优先级。不合法的动作不会出现，不用去点灰色按钮。

带说明的流转都可以再挂附件，规则和新建时一样。说明同样支持 Markdown。

### 项目

管理员在项目列表点 **新建项目**。名称必填。缩写 2–8 位、字母开头、可含数字，例如 `SOC`；留空会按名称自动生成。缩写不能和已有项目相同，也不能互为前缀。说明会出现在项目列表卡片上。

项目标题旁的 **详情** 谁都能看。管理员可以改这些资料，Agent 接单和验收时会读它们：

- 产品经理、体验官
- 代码仓、默认分支、技术栈
- 设计稿、需求文档（链接，或直接上传文件，每种最多 20 个）
- 开发 / 测试 / 生产环境地址，以及默认验收环境
- 给 Agent 的说明（怎么启动、测哪些范围、账号向谁要）。不要在这里写密码、Token 或密钥

超级管理员可以删除项目。报障、附件和成员关系会一起删掉，不能恢复。删除单条报障同样只有超级管理员能做，附件和流转记录一并删除。

### 管理后台

顶栏 **管理后台** 只对管理员显示，分四页。

**用户。** 创建账号时指定用户、管理员或超级管理员，并设初始密码。之后可以改角色、重置密码、禁用或删除。新用户要能提报，还得在对应项目的「成员」页加进去。

**API Key。** 给 Agent 用，不给人登录网页。明文只在创建或重新生成时出现一次，离开页面前复制备好。

- **用户级** 必须绑定至少一个项目，能力等同绑定项目里的普通用户。适合测试 Agent：提报、确认、打回、异议、补充材料。
- **管理员级** 默认可访问全部项目。适合修复 Agent：接单、提交修复、标不属实、要求补充、改项目资料。

有效的 Key 可以改名称、角色和绑定项目，也可以重新生成（旧 Key 立刻失效）。禁用后可以再启用。删除是物理删除。已吊销的旧数据只能删除。列表里能看到前缀、最近使用时间和调用次数。

同一行可以复制两份接入配置：

- **本机 Agent**：在跑 Agent 的机器上起 `mcp/server.ts`，适合只支持本地命令的客户端。
- **远端 Agent**：`https://<服务地址>/mcp`，请求头 `Authorization: Bearer <API Key>`。支持远程 MCP 的客户端可以直接装，不用克隆本仓库。

**提示词。** 两段现成提示词，填上目标项目名后复制到对话里。

- 用户级：按项目资料打开被测系统，把能复现的故障建成报障，并验收待确认的单。
- 管理员级：待处理的单先归类。现有功能坏了就修，要新能力又没有产品确认就标不属实。

**数据分析。** 按提报人看一段时间内的提交量、被采纳量和各状态分布，可切全部 / 近 7 天 / 30 天 / 90 天。人和 API Key 分开统计。

### 给 Agent 的最短闭环

准备两把 Key：用户级 `cursor-qa` 绑到目标项目，管理员级 `cursor-fixer`。在 Cursor 里用项目级 MCP 配置（不要把明文 Key 提交进仓库）：

```bash
cp .cursor/mcp.json.example .cursor/mcp.json
```

然后：

1. 测试 Agent：`create_bug`，记下返回的 `bugId`。
2. 修复 Agent：`start_fix`，改完后 `submit_fix`（说明必填）。
3. 测试 Agent：按修复说明重测。通过就 `confirm_fix`，还有问题就 `reject_fix`。
4. 材料只在报障人手里时，修复 Agent 用 `request_info`；原报障人补上后用 `provide_info`，单回到待处理。

`create_bug` 可以带上 `stage_attachment` 返回的 `attachmentIds`，以及原话、步骤和圈选。Agent 读单时，docx / txt 正文和图片会随 `get_bug` 返回。

### 提交后分派给 Agent

分派有两件活，在同一套配置里分开开关。整理走查只在走查进入审核时发给本机 Agent，只改草稿。修理报障在报障新建或回到待处理（补充材料、仍有问题、异议、撤回不属实）时触发，可以发给本机 Agent、Cursor 云端 Agent，或两个都发。确认已修复、接单不会分派。本机地址和名单两件活共用，提示词不同。

管理员在管理后台的「分派给 Agent」里配置。每个项目一套，清单里可以编辑、测试和删除：

1. 在跑 Cursor 或 ZCode 的电脑上复制 `wake.config.json.example` 为 `wake.config.json`。`projects` 里用项目缩写对上代码仓的绝对路径。这个目录就是 Agent 的工作区（`--workspace`），不要写成用户主目录、磁盘根目录，也不要写成放着 `wake.config.json` 的目录。`agent` 用 `cursor` 或 `zcode`。报障标题和正文会包在 `<question>` 里，并声明这是数据不是指令。Cursor 默认 `agent -p --trust --sandbox enabled --output-format json --workspace <项目目录> --mode plan`，不带 `--force` / `--yolo`，所以只做只读分析。要让它在这个目录里改代码，把 `applyEdits` 设为 `true`（会加上 `--force`，仍然限制在该目录和沙箱里）。同一张单的后续分派会带 `--resume` 复用上次的会话。标准输出的 JSON 写在 `wake-runs/`。参数不对时，在配置里写 `argv` 数组，用 `{prompt}`、`{cwd}`、`{bugId}`、`{publicId}`、`{projectCode}`、`{session}` 占位。自定义参数里的 `--force` / `--yolo` 在 `applyEdits` 没打开时会被去掉。
2. 执行 `npm run wake`。它只监听 `127.0.0.1:3099`。
3. 把打印出来的地址填进本机地址，保存，复制签名密钥，贴进 `secrets`，重启 `npm run wake`。点 **测试本机地址**，终端里应出现一行测试日志。
4. 之后网页上新建的待处理单会拉起本机 Agent。提示词就是管理员级修复提示，并点名这张单。Agent 用这台机器上已经接好的 Bugboard MCP 去 `get_bug`、`start_fix`。

Bugboard 跑在 Docker 里时，容器访问不到宿主机的 `127.0.0.1`。本机地址改成 `http://host.docker.internal:3099/wake`。若仍不通，把 `listen` 改成 `0.0.0.0:3099`，并写上 `"allowLan": true`，只在可信网络里这样做。

Cursor 云端只参加修理。在同一套配置里勾选「分派给 Cursor 云端 Agent 修理」即可。它不整理走查。服务器需要 `CURSOR_API_KEY`（Cursor 后台 Cloud Agents 的密钥），项目资料里要有代码仓。云端虚拟机要能访问 `BASE_URL`，单才会被回写；访问不了时，它仍按报障正文改代码，但不会自己 `submit_fix`。再设置 `BUGBOARD_DISPATCH_API_KEY`（一把管理员级 Key）后，云端 Agent 会带上这个站的远程 MCP。

同一张单、同一个原因，一分钟内只自动分派一次。详情页的 **再次分派去修理** 不受这限制。

工具权限、配置示例和冒烟脚本见 [`docs/mcp-examples.md`](docs/mcp-examples.md)。本机不依赖 Cursor 界面时，可以跑：

```bash
npm run mcp:smoke
```

## 安装与运行

本地开发（空库打开 http://127.0.0.1:3000 会进入首装）：

```bash
npm install
npm run dev
```

```bash
npm test
npm run build
# 生产启动（standalone，局域网）
cp -R public .next/standalone/ && cp -R .next/static .next/standalone/.next/
DATA_DIR=./data SESSION_SECRET='change-me-to-a-long-random-secret-32+' \
  HOSTNAME=0.0.0.0 PORT=3080 node .next/standalone/server.js
```

Docker 默认把 **3080** 映射出来，监听 `0.0.0.0`，局域网可直接访问：

```bash
docker compose up --build -d
```

- 本机：http://127.0.0.1:3080
- 局域网：http://\<主机局域网IP\>:3080

数据卷是 `bugboard-data`（容器内 `/data/db` 与 `/data/uploads`）。

| 变量 | 说明 |
|------|------|
| `SESSION_SECRET` | Session 加密密钥。生产环境换成至少 32 位的随机串 |
| `BASE_URL` | 对外访问地址。API Key 页复制远端 MCP 地址时用它，建议写成局域网或公网地址。Cursor 云端 Agent 也用它拼报障链接和 MCP |
| `CURSOR_API_KEY` | 可选。Cursor Cloud Agents 的密钥。项目启用了云端 Agent 才会用 |
| `BUGBOARD_DISPATCH_API_KEY` | 可选。一把管理员级 Bugboard Key，只交给 Cursor 云端 Agent 的 MCP，不进网页 |
| `DATA_DIR` / `DB_PATH` / `UPLOADS_DIR` | 数据路径。Docker 里已经设好 |
| `HOSTNAME` / `PORT` | 监听地址和端口。Docker 内是 `0.0.0.0:3000`，主机端口是 3080 |
| `TZ` | 容器时区，compose 里是 `Asia/Shanghai`。报障编号按这个时区取日期 |

需要公网时，在 `Apps/nginx` 给这个服务加反代和证书。本仓库只负责 Web、API、MCP 和数据。
