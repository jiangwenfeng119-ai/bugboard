Bugboard 是内网多项目报障台账：提报 → 判定/修复 → 原报障人确认。本文说明 **Bugboard 产品本身** 的用法；各被测项目在 Git 上的改动请见项目内的 **变更** Tab（与右上角菜单里的「版本与更新日志」不是一回事）。

### 用户怎么用

1. 登录后从 **项目** 进入你有权限的项目，在 **报障** 中点 **新建报障**。这一屏分两步：上面 **问问项目助理** 可以不填，下面 **再写这张报障** 可以直接建单。不确定功能有没有、入口在哪时，先在上面提问；只回答，不改代码，也不替你提交。等回答出来后，判断是「建议报障」或「没有把握」，点 **整理并填入报障**，问题和回答会整理进标题和描述，改完再提交。判断是「已经有了」时一般不用建单。现象清楚也可以不问，直接写标题、正文、优先级，并可拖拽/粘贴图片、录音或上传附件。
2. 项目列表顶部的 **待我处理** 列出这个账号现在要跟进的单。主路径是 **待处理** → **修复中** → **待发布** → **待确认** → **已确认**。要一个现在没有的能力时，会先到 **待产品经理确认**，再决定做（回到修复中）或不做（标为不属实）。也可能直接被标为 **不属实**。待发布还没上线，这一步不能确认，也不能打回。
3. **待确认** 时，原报障人能点 **确认已修复** 或 **仍有问题**。API Key 提交的单，该项目的管理员也可以点 **确认已修复**。仍有问题会回到 **待处理**，这一步仍只有原报障人。
4. 若被标 **不属实**，可 **提出异议**（回到待处理）或 **认可不属实**（终态 **已认可**）。
5. 修复方可能 **要求补充**；在详情里点 **补充材料** 回复即可。待处理时，原报障人也可以写 **补充说明**，这不改变状态。

### 管理员怎么用

管理员除用户能力外，还可：

1. 在 **管理后台** 创建账号、项目、分配成员、管理 API Key。后台还有数据分析、分派给 Agent、行为、提示词。成员页能把人设成该项目的用户或管理员。
2. 打开项目查看汇总、走查与趋势。网页上要 **接单**、写修复说明、**标为不属实** 或 **请产品经理确认**，这个人得是该项目成员里的管理员。账号管理员能打开全部项目、维护成员名单；自己没被设成项目管理员时，不能改报障状态。管理员级 API Key 在它能访问的项目上视为项目管理员，并且只有超级管理员能创建和管理这种 Key。
3. 为项目配置修复 Agent 和发布。发布方式默认是不自动部署。设成本机重启或云上部署并写了定时之后，才会在那个时刻入队。需要时用 **紧急发布** 入队，由本机发布任务领走，不会在网页进程里直接部署。
4. 打开项目 **变更** Tab，查看该被测项目在 Git 上的 fix/feature/chore/release 账本（由 Agent 经 MCP 写入，不是 Bugboard 产品 changelog）。能进项目的人都能看；登记和发布要项目管理员。

### 待发布与夜间发布

修复 Agent **提交修复**（`submit_fix`）后，单进入 **待发布**，不会立刻变成 **待确认**。含义：代码已 push，但尚未部署到你验收的环境。

- **定时发布**：不是默认开启的。项目要先把发布方式设成本机重启或云上部署，并填写定时（如 `22:00`）。到点后，若还有待发布内容，才入队，然后 sync → 部署。默认会把对应单批量迁入 **待确认**。管理后台「行为」里可以关掉这次推进，成功也留在待发布。
- **紧急发布**：项目管理员可对选中单入队。领走之后和定时是同一套本机流程，只适合必须马上验的场景。网页上的「标记已发布」不跑部署，只记账并按上面的开关决定要不要进入待确认。
- 发布失败时单会留在 **待发布**。失败说明出现在项目的 **变更** 页，需处理后再发。执行中的任务超过该项目的超时（默认 45 分钟）没有回写，会记失败并允许下一次入队。这次检查发生在下一次入队或领取时。

流程上应先 **commit 并 push**，再提交修复说明。服务端不检查 git，只看单的状态和说明。发布与 push 分离，避免未同步代码被部署。

### 项目「变更」Tab 与产品更新日志

二者不要混用：项目 Tab 记的是**被测业务系统**在 Git 上的账本；菜单里的日志记的是 **Bugboard 产品**自身发版。

## 项目 **变更** Tab

- **记录谁**：被测项目在 Git 远端上的改动与发布。代码仓地址存在项目资料的 `github_url` 字段里，比对时接受 `https`、`http` 或 `git@主机:路径`，不限于 GitHub
- **谁维护**：修复/开发 Agent（MCP `record_change`）与发布任务
- **入口**：项目页 **变更**

## 用户菜单 **版本与更新日志**

- **记录谁**：**Bugboard 报障系统** 自己的发版说明
- **谁维护**：产品维护者更新仓库内 `CHANGELOG.md`
- **入口**：顶栏头像 → **版本与更新日志**（`/changelog`）

产品手册（本页）与版本日志面向所有已登录用户；管理后台使用同一顶栏菜单。
