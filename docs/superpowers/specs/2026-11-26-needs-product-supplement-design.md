# 待产品经理确认时，报障人可以补充说明 — Design

日期：2026-11-26  
状态：已实施。

报障停在待产品经理确认时，原报障人可以写补充说明，帮助产品经理理解并处理这一张。状态保持待产品经理确认。说明出现在时间线上。标题、正文、附件或这句说明里写「已经确认」，仍然要产品经理在系统里点「可以做」或「不做」。

## 现在

[`canAddSupplement`](../../../src/lib/services.ts) 里，项目管理员任何状态都能写。原报障人只在待处理时能写。详情页「下一步」在 `canSupplement` 为真时显示「补充说明」。提交走现有的 `POST /api/bugs/:id/supplements`，事件 `kind` 为 `supplement`，`from_status` 与 `to_status` 都是当前状态。网页可附图，用户级 Key 的 `add_supplement` 只传说明。

叫醒只在补充之后状态仍是待处理、且该项目打开了「待处理时补充说明」时发生。待产品经理确认时，修复 Agent 停住，等人点「可以做」。

用户级测试提示词写着：待产品经理确认没有报障人动作。

## 谁能写

原报障人在这两种状态可以写：待处理、待产品经理确认。原报障人是创建这张单的登录用户，或创建这张单的那把 API Key。别人提的单，原报障人不能写。

项目管理员仍然任何状态都能写。这一份不收紧管理员。

其余状态，原报障人不能写。修复中、待补充、待发布、待确认、已确认、不属实、已认可都保持现在的拒绝。待补充仍走「补充材料」。

说明为空时，仍拒绝，文案仍是「请填写补充说明」。

原报障人在不允许的状态写时，文案改为：「只有待处理或待产品经理确认时，原报障人才能补充说明；接单后请用要求补充流程」。

可以多次写。每次各一条时间线。

## 写进去之后

用现有的 `addBugSupplement`。不新增事件种类，不新增接口。

- 状态保持待产品经理确认
- 处理人不变。补充说明不计入处理人；处理人仍是把单送进当前状态的那一次流转
- 时间线标题仍是「补充说明」
- `updated_at` 更新
- 网页上的附件仍挂在这条事件上
- 不叫醒修复。现有判断「只有待处理才叫醒」保持不变。「行为」里的叫醒文案仍是「待处理时补充说明」
- 收件箱不新增一类。产品经理仍在「待产品经理确认」里打开这张单，在时间线里读到说明

详情页按钮文案仍是「补充说明」。展开后的提示按状态区分：

- 待处理：保持现在这句。写给处理人和 Agent，补清背景、期望或遗漏的细节。不改变状态，会出现在时间线里。
- 待产品经理确认：写给产品经理，把这张单想要的能力、背景和遗漏说清楚。状态仍是待产品经理确认。写已经确认也不算点过「可以做」或「不做」。

`GET /api/bugs/:id` 在能写时，`actions` 里仍带 `add_supplement`。

## Agent

用户级测试提示词：

- 写操作里加上 `add_supplement`。待处理或待产品经理确认，且是自己提的单。说明必填。状态不变。
- 人让它向产品经理补充某一张待产品经理确认的单时，才调用。没让它补，就不要写。
- 说明写给产品经理：这张单想要的能力、背景、遗漏。不要写「产品经理已经确认」或同类说法。
- 第 15 条改为：待产品经理确认时，原报障人可以 `add_supplement`。状态保持待产品经理确认。可以做、不做仍只认系统里的点击。

管理员级修复提示词：

- 人点名讨论待产品经理确认时，先列出现象、要的新能力、报障人后补的说明（`kind` 为 `supplement`），以及请产品经理确认那条里的建议。没有后补说明就写明没有。没有建议也写明没有。
- 已有规则保持：后补说明要当背景读，不算产品确认。不要代点「可以做」或「不做」。

`add_supplement` 的工具说明改为：管理员级 Key 任意时候可用；原报障人 Key 在待处理或待产品经理确认时可用。待产品经理确认时，说明写给产品经理，不改状态，也不算已经点过「可以做」或「不做」。

## 文档

改这几处里「原报障人仅在待处理时可写」的说法，加上待产品经理确认：

手册里写清：待产品经理确认时，原报障人可以写补充说明，帮助产品经理理解这一张。状态不变。写已经确认也不跳过「可以做」或「不做」。

## 测试

[`tests/services.test.ts`](../../../tests/services.test.ts) 在现有补充说明用例上加：

- 进入待产品经理确认后，原报障人 `canAddSupplement` 为真
- 写一条说明后，状态仍是待产品经理确认，事件 `kind` 为 `supplement`
- 修复中、待补充时，原报障人仍不能写

叫醒不另写分派断言。`addBugSupplement` 里仍只在补充后状态是待处理时叫醒，本用例用「状态仍是待产品经理确认」守住这个条件。

[`tests/agent-prompts.test.ts`](../../../tests/agent-prompts.test.ts) 锁住：用户级提示词允许在待产品经理确认时 `add_supplement`，并写明没让它补就不要写、写已经确认不算点过。管理员级提示词讨论这类单时要列出报障人后补的说明。

## 不做什么

- 不新开「向产品经理说明」按钮或事件种类
- 不把单退回待处理，也不改成待补充
- 不因为这句说明叫醒修复，也不代点「可以做」或「不做」
- 不让非原报障人的普通成员写
- 不改管理员「任何状态都能写」
- 用户级 Key 仍只传文字说明。附图仍走网页
