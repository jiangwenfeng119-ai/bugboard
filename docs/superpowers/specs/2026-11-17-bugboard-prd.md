## 1. 背景与目标

内网多项目报障台账。人和 Agent 走同一套状态机。

1. 用户或测试 Agent 在指定项目里提交报障：文字、图片、视频、文档、音频，可录音、粘贴、圈图，也可录一段走查再整理成多张单
2. 项目管理员或修复 Agent 判定。现有功能坏了就修。要一个现在没有的能力、而且提交时还没写已经确认，先请产品经理确认，不标成不属实
3. 修复说明提交后进入待发布。默认要等发布成功，原报障人才能验收
4. 原报障人确认已修复，或打回。不属实可以异议，也可以认可为终态
5. 项目内可看汇总和被测仓库的变更账本。Bugboard 自己的发版说明在另一处

不做通用 Jira / Canny。没有邮件、即时消息或实时推送，刷新列表即可。

### 成功标准

- 账号分用户、管理员、超级管理员。项目成员另分用户和管理员。两套角色不要混用
- 空库首装创建第一个超级管理员。之后只有管理员开户，没有自助注册
- 状态机在服务端校验。每次流转有操作人、时间和说明
- REST 与 MCP 共用同一套权限。API Key 只有用户级和管理员级
- 单容器 Docker 可在内网跑。发布和叫醒跑在有代码仓的电脑上，不在容器里跑 git

## 2. 角色与权限

### 2.1 账号角色

| 能力 | 用户 | 管理员 | 超级管理员 |
|------|:----:|:------:|:----------:|
| 登录，改自己的密码 | ✓ | ✓ | ✓ |
| 空库首装 | | | 第一个账号 |
| 开户、改角色、禁用、删除账号 | | ✓ | ✓，且可任命超级管理员 |
| 创建项目、改项目资料、维护成员、管 API Key、进管理后台 | | ✓ | ✓ |
| 打开项目 | 仅成员名单内 | 全部 | 全部 |
| 删除项目、删除单条报障 | | | ✓ |

密码至少 6 位。禁用后不能登录。普通管理员不能改超级管理员，也不能删除或禁用自己正在登录的账号。不能删除、禁用或降级最后一个超级管理员。没有超级管理员时，不能把最后一个仍启用的管理员降成用户，也不能删掉他。

账号管理员可以维护成员名单，即使自己还不是该项目的管理员。新建项目不会自动把自己写进成员表，所以必须允许账号管理员加入第一个项目管理员。

### 2.2 项目成员角色

成员只有用户和管理员。网页上这些动作看项目成员角色，不看账号是不是管理员：

接单、提交修复说明、标不属实、请产品经理确认、可以做、不做、要求补充、撤回不属实、撤回修复提交、改优先级、立即发布、标记已发布、登记代码变更。

账号是用户、但成员角色是管理员时，可以做上面这些事，但看不到管理后台，也看不到「成员」页。账号是管理员、但不是该项目的管理员时，能打开项目和维护名单，详情里的处理动作是空的。

### 2.3 API Key

Key 不用于登录网页。明文只在创建或重新生成时出现一次，库存哈希。可以改名称、角色和绑定项目，可以禁用后再启用，也可以物理删除。已吊销的旧数据只能删除。

| | 用户级 | 管理员级 |
|--|--|--|
| 角色 | `user` | `admin` |
| 项目范围 | 必须至少绑定一个项目 | 默认可访问全部项目，不必绑定 |
| 报障 | 在绑定项目里提报、看单、上传。确认、打回、异议、认可不属实、补充材料只针对自己提的单 | 包含这些，并且在可见项目上视为项目管理员 |
| 不能做 | 处理别人的单，改状态，发布 | 不能是超级管理员，因此不能删除项目或报障。创建和修改 Key 必须是人类管理员 |

管理员级 Key 可以调用账号管理员的部分接口，例如维护成员。创建 Key 本身不行。

原报障人是创建那张单的账号或那把 Key。别人不能代为确认、打回、异议、认可或补充材料。

## 3. 状态机

| 状态 | 含义 |
|------|------|
| 待处理 | 新单，或打回、异议、补充材料、撤回不属实之后 |
| 修复中 | 已接单，或产品经理点了可以做 |
| 待补充 | 缺的材料只在报障人手里 |
| 待产品经理确认 | 要一个现在没有的能力，提交时还没写已经确认 |
| 待发布 | 修复说明已提交，代码应已 push，还没上到验收环境 |
| 待确认 | 已发布，等原报障人验收 |
| 已确认 | 终态 |
| 不属实 | 现象不存在、没用对、配置不对，或产品决定不做 |
| 已认可 | 原报障人认可不属实。终态，不能再异议或撤回 |

### 允许的转换

「项目管理员」对人类指项目成员角色。对管理员级 API Key，指它能访问的项目。

| 动作 | 谁 | 从 | 到 | 说明 |
|------|----|----|----|------|
| 接单 | 项目管理员 | 待处理 | 修复中 | 可选 |
| 提交修复说明 | 项目管理员 | 修复中 | 待发布 | 必填。调用前须已 commit 并 push |
| 发布后待确认 | 项目管理员或发布任务 | 待发布 | 待确认 | 说明可选。失败不改状态。项目可关掉「成功后推进」，成功也不改状态 |
| 确认已修复 | 原报障人 | 待确认 | 已确认 | 可选 |
| 仍有问题 | 原报障人 | 待确认 | 待处理 | 必填 |
| 请产品经理确认 | 项目管理员 | 待处理、修复中 | 待产品经理确认 | 必填 |
| 可以做 | 项目管理员 | 待产品经理确认 | 修复中 | 可选 |
| 不做 | 项目管理员 | 待产品经理确认 | 不属实 | 必填 |
| 标为不属实 | 项目管理员 | 待处理、修复中 | 不属实 | 必填 |
| 提出异议 | 原报障人 | 不属实 | 待处理 | 必填 |
| 认可不属实 | 原报障人 | 不属实 | 已认可 | 可选 |
| 撤回不属实 | 项目管理员 | 不属实 | 待处理 | 必填 |
| 要求补充 | 项目管理员 | 待处理、修复中 | 待补充 | 必填 |
| 补充材料 | 原报障人 | 待补充 | 待处理 | 必填 |
| 撤回修复提交 | 项目管理员 | 待发布 | 修复中 | 必填 |

补充说明写入时间线，`kind` 为 `supplement`，不改状态。项目管理员随时可写。原报障人仅在待处理时可写。后补说明不算提交时的产品确认。

带说明的流转可以再挂附件。不合法的动作不出现。

产品确认只认提交时的标题、正文和附件，以及从待产品经理确认转到修复中的那一次「可以做」。时间线和后补说明里的确认不算。

## 4. 报障、附件与走查

### 4.1 主字段

- 标题，必填，最长 200 字
- 正文，最长 20000 字。支持 Markdown：二级标题、空行分段、有序列表
- 项目、优先级、状态
- 报障编号：项目缩写 + 固定东八区 `YYMMDD` + 当天序号（至少 3 位）。不读 `TZ`
- 原报障人、创建时间、更新时间
- 可选证据：原话、步骤、圈选、页面地址、走查时间点

一条报障只写一个现象。优先级不选就是 P2。

| 级别 | 何时选用 |
|------|----------|
| P1 | 核心流程不可用、崩溃、错误结果、数据风险 |
| P2 | 能用，但行为不对或不稳定 |
| P3 | 不挡使用，偏界面、文案、交互 |

项目管理员可改优先级。列表可按状态、优先级、提交人筛选，可搜标题或编号，表头可排序。状态筛选分成进行中和终态。

### 4.2 附件

网页和 REST：单文件不超过 50MB，一条最多 20 个。类型为 png、jpg、jpeg、gif、webp、mp4、webm、mov、pdf、docx、xlsx、txt、md、zip、mp3、wav、ogg、m4a。可拖入、粘贴图片、录音。

MCP `stage_attachment` 在调用 REST 之前把单文件限制为 8MB。

文件存在本地磁盘。下载要登录，并且能看所属项目。附件可挂在报障上，或挂在某次流转上。

`ASR_BASE_URL` 和 `ASR_API_KEY` 都配置时，录音可以走服务端转写，模型名默认 `whisper-1`。缺任何一个时，转写接口返回不可用，不去调外部服务。

### 4.3 走查与嵌入上报

走查先变成草稿，人看完才收成报障。默认停顿超过 1.2 秒新开一条，不足 8 个字标成待确认，整理超过 8 分钟改用规则草稿。这些可以按项目改。

嵌入式上报用项目上的 widget token，不走登录态。同一 token 加 IP，10 分钟最多 30 次。

## 5. 项目、汇总、收件箱、变更

项目名称必填。缩写 2–8 位，字母开头，大写字母或数字，不能与已有缩写相同或互为前缀。留空则按名称生成。

Logo 为 png、jpg、jpeg、webp，单张不超过 2MB，再传会替换。详情谁都能看。账号管理员可改：产品经理、体验官、代码仓、默认分支、技术栈、设计稿、需求文档、三个环境地址、默认验收环境、给 Agent 的说明。设计稿和需求文档每种最多 20 个文件。说明里不要写密码、Token 或密钥。

汇总：总数、各状态数量，以及 7 / 30 / 90 天的每日新建和各状态流入。

待我处理按项目分组，只列出这个身份现在要跟进的单。原报障人看到自己的待确认、不属实、待补充。项目管理员默认还看到待处理、待产品经理确认、待发布，以及自己接手的修复中。待处理默认最多列 8 条。

项目卡片上，账号管理员看到整个项目的待处理、待补充、待发布、待确认。账号是用户时只看到待补充和待确认；若此人已是项目管理员，这两项是整个项目的数量。

变更页记的是被测仓库的 fix、feature、chore 和发布，不是 Bugboard 自己的更新日志。能进项目的人都能看。登记和发布要项目管理员。

## 6. 信息架构

1. 登录。10 分钟内同一用户名失败满 8 次，或同一 IP 满 40 次，暂时拒绝
2. 首装，仅空库
3. 项目列表，含待我处理。账号管理员可新建项目。超级管理员可删除项目
4. 项目页
   - 报障
   - 走查
   - 汇总
   - 变更
   - 成员，仅账号管理员
5. 报障详情：下一步、正文、附件、时间线
6. 管理后台，仅账号管理员。默认数据分析，顺序为：数据分析、用户、API Key、分派给 Agent、行为、提示词
7. 产品手册 `/help`、版本与更新日志 `/changelog`。日志读仓库里的 `CHANGELOG.md`，版本号读 `package.json`

## 7. 数据模型（逻辑）

- **User**：username，passwordHash（bcrypt），role（`user` | `admin` | `superadmin`），active，时间
- **Project**：name，slug，code，description，资料字段，logo，widget token，时间
- **ProjectMember**：projectId，userId，role（`user` | `admin`）
- **Bug**：projectId，publicId，title，body，priority，status，reporterType，reporterId，时间，以及可选证据字段
- **BugStatusEvent**：bugId，from，to，actorType，actorId，note，kind（`transition` 或 `supplement`），时间
- **Attachment**：挂在报障或某次事件上
- **ApiKey**：name，keyHash，keyPrefix，role（`user` | `admin`），创建人，最近使用，调用次数，disabledAt，revokedAt
- **ApiKeyProject**：仅用户级 Key 使用
- **ProjectDocument**：kind 为 `design` 或 `docs`
- **ProjectDispatch**：叫醒地址、云端开关、发布方式、发布命令、定时，以及行为开关
- **AgentDispatch**：一次分派或一次发布任务
- **ProjectChange**：kind 为 `fix` | `feature` | `chore` | `release`，提交 SHA，关联报障，发布结果

库是 SQLite。附件在本地目录。

## 8. API 与 MCP

### 8.1 认证

- 网页：cookie `bugboard_session`，HttpOnly
- Agent：`Authorization: Bearer <API Key>`。有有效 Key 时优先于 cookie
- 生产环境必须设置 `SESSION_SECRET`，且不能是开发默认值。代码不检查最短长度
- 远端 MCP 在 `/mcp`。`POST` 和 `DELETE` 要 Key。`GET` 返回 405，不做长连接 SSE。工具在进程内回连 `http://127.0.0.1:$PORT`
- 本机 MCP 进程用 `BUGBOARD_BASE_URL` 和 `BUGBOARD_API_KEY`

登录后的错误里，无权为 403，不存在为 404，未登录为 401。

### 8.2 REST

UI 和 MCP 共用 REST。路径、方法和字段以 [`docs/api.md`](../../api.md) 为准。流转提交的是动作名，不是目标状态。

### 8.3 MCP

工具以 [`docs/mcp-examples.md`](../../mcp-examples.md) 为准。用户级 Key 不能做处理动作。`run_release` 只入队。`mark_released` 不跑部署。`upload_project_logo` 接受 png、jpg、jpeg、webp，不超过 2MB。

## 9. 分派与发布

分派有两件活，配置分开，本机地址共用。

叫醒默认：网页、小组件、走查建单会叫；API Key 建单不叫。补充材料、仍有问题、异议、撤回不属实、待处理时的补充说明，以及登录用户点「可以做」，会再叫一次。API Key 点的「可以做」不再开一轮。确认已修复、接单、请产品经理确认不叫。同一张单、同一个原因，一分钟内只自动叫一次。详情里的再次分派不受这限制，操作者是账号管理员。

Cursor 云端只参加修理。需要 `CURSOR_API_KEY`。要让云端带上本站 MCP，再设 `BUGBOARD_DISPATCH_API_KEY`。云端要能访问 `BASE_URL`，才会自己回写。

发布在有代码仓的电脑上跑。发布方式默认不自动部署，另有本机重启和云上部署。定时是 `HH:MM`，留空则不参加。`--schedule` 用固定东八区的当前时刻去对，不是写死 22:00。只有方式会自动部署、时刻相同、并且还有待发布内容，才入队。

紧急发布只入队。配了本机地址时，叫醒服务再拉起发布任务。命令必须是一条绝对路径，不能是 shell，并且要落在 `/Users`、`/opt`、`/usr`、`/homebrew` 或该项目工作区里。工作区不干净，或本地与远端已经分叉，就记失败，报障留在待发布。执行中的任务超过该项目的超时（默认 45 分钟，可改 5–180）没有回写，会在下次入队或领取时记失败。

领取队列的 Key 必须是账号管理员，并且是该项目的管理员。管理员级 Key 满足前者，并在可见项目上满足后者。

## 10. 技术与部署

- Next.js 全栈单体，SQLite，本地附件
- Docker：主机 `3080` 映射容器 `3000`，数据卷挂 `/data`
- 未传入 `BASE_URL` 时，compose 回落到 `http://127.0.0.1:3080`。局域网或公网入口写在部署环境的 `BASE_URL` 里。这个值用于复制 MCP 地址和云端回写，不决定容器听哪张网卡
- 报障编号和页面时间按固定东八区计算，不读 `TZ`。容器仍把 `TZ` 设为 `Asia/Shanghai`
- 环境变量清单以 README 的表为准

### 安全

- 除首装、登录、登出和嵌入式上报外，都要身份
- 上传有扩展名和大小限制，不执行用户文件
- 状态机在服务端校验
- API Key 可禁用、吊销、删除。操作写入时间线

## 11. 明确不做

- 邮件、即时消息、WebSocket 实时通知
- 自助注册、OAuth、免登录的网页（嵌入式上报除外，它用项目 token）
- 投票、路线图、多租户计费
- 所见即所得富文本、多语言
- 对象存储、多实例水平扩展
- 除账号三角色和项目两角色之外的自定义角色

产品自身的更新日志已经有，记在 `CHANGELOG.md`。被测项目的 Git 账本记在项目的变更页。两者不是一回事。

## 13. 决策摘要

| 主题 | 决策 |
|------|------|
| 确认权 | 只在原报障人 |
| 两种管理员 | 账号管理员管人和名单。项目管理员管单和发布 |
