- **日期**：2026-11-03

- **架构选型**：方案 1 — Next.js 全栈单体 + SQLite + 本地磁盘附件 + 同仓 REST API / MCP

## 1. 背景与目标

自建一个足够薄的报障网页，覆盖完整闭环：

1. 用户（或测试 Agent）在指定项目中提交 bug（文字 + 图片/视频/文档/音频，支持麦克风录音）
2. 管理员（或修复 Agent）查看、判定：不属实写原因，或属实后修复并写说明、推进状态
3. 原报障人复测并确认已修复，或打回
4. 项目内可查看汇总：总数、分状态数量、按时间的趋势；所有状态变化带时间戳

不做通用 Canny/Jira，字段与流程刚好够用即可。

### 成功标准

- 管理员可创建多个项目（一项目对应一应用），并把用户分配进项目
- 用户名密码登录；角色仅 `用户` / `管理员`
- 报障支持多媒体与浏览器录音
- 状态机完整可用，每次变更可审计
- 提供 REST API + MCP；API Key 分用户级 / 管理员级，便于「测试 Agent A」与「修复 Agent B」分工
- 项目汇总页可读、趋势图可用
- 单容器 Docker 内网可跑；公网访问时在 nginx 网关增加反代即可

## 2. 角色与权限

### 2.1 人类账号

| 能力 | 用户 | 管理员 |
|------|:----:|:------:|
| 登录（用户名 + 密码） | ✓ | ✓ |
| 空库首装创建第一个管理员 | | ✓ |
| 创建/禁用账号、指定角色 | | ✓ |
| 创建/编辑项目、分配成员 | | ✓ |
| 管理 API Key（创建/吊销、选角色与项目） | | ✓ |
| 在**所属项目**内报障、查看、传附件/录音 | ✓ | ✓（默认可访问全部项目） |
| 推进：待处理→修复中→待确认；标不属实 | | ✓ |
| 写修复说明 / 不属实原因（可带附件） | | ✓ |
| 确认已修复 / 仍有问题 / 对不属实有异议 | 仅**原报障人** | — |
| 查看项目汇总 | 所属项目 | 全部项目 |

**账号开通**：首次启动空库进入 setup，创建第一个管理员；之后仅管理员可创建账号（创建时选择角色）。不开放自助注册。

**项目可见性**：管理员把用户分配到项目；用户只能看到被分配的项目。管理员默认可见全部项目（不依赖成员表，也可写入成员表以便统一展示）。

### 2.2 API Key（Agent 身份）

API Key 是可审计的机器人身份，**权限模型与人类角色对齐，且管理员级 Key 必须包含用户级 Key 的全部能力**。

| | 用户级 Key（如测试 Agent A） | 管理员级 Key（如修复 Agent B） |
|--|--|--|
| 角色 | `user` | `admin` |
| 项目范围 | 创建时必须绑定一个或多个项目 | 默认可访问全部项目 |
| 能力 | 同普通用户：在所属项目创建 bug、上传附件、查看报障与汇总；对自己创建的 bug 可确认/打回/异议 | **包含用户级全部能力**，外加状态流转（修复中/待确认/不属实）、写说明、用户/项目/成员/Key 管理 |
| 认证 | `Authorization: Bearer <api_key>` | 同左 |

**闭环示例**：

- Agent A（用户级 Key）在项目中创建 bug → 成为该单「原报障人」
- Agent B（管理员级 Key）查单、修复、提交修复说明 → `待确认`
- Agent A 再确认或「仍有问题」打回

状态历史记录 `actorType=api_key`、Key 名称与时间戳，便于区分是哪个 Agent 操作。

明文 Key 仅在创建时显示一次；只存哈希；支持吊销。

## 3. 状态机

| 状态 | 含义 |
|------|------|
| `待处理` | 新单，或被打回后重新打开 |
| `修复中` | 管理员/管理员级 Key 已接单 |
| `待确认` | 已提交修复说明，等待原报障人验收 |
| `已确认` | 原报障人确认修好（终态） |
| `不属实` | 判定无效并填写原因；原报障人可异议 |

### 允许的转换

| 从 | 到 | 谁 | 必填 |
|----|----|----|------|
| 待处理 | 修复中 | 管理员 / 管理员级 Key | — |
| 待处理 / 修复中 | 不属实 | 管理员 / 管理员级 Key | 原因（可带附件） |
| 修复中 | 待确认 | 管理员 / 管理员级 Key | 修复说明（可带附件） |
| 待确认 | 已确认 | 原报障人（人或其用户级 Key） | — |
| 待确认 | 待处理 | 原报障人 | 「仍有问题」说明（可带附件） |
| 不属实 | 待处理 | 原报障人 | 「有异议」说明（可带附件） |

每次转换写入 `BugStatusEvent`：`from`、`to`、`createdAt`、`actorType`、`actorId`、`note`、关联附件。

**一期不做**：管理员从 `修复中` 退回 `待处理`（若后续需要再加）。

## 4. 报障与附件

### 4.1 主字段

- 标题（必填）
- 描述（纯文本；附件独立区，避免富文本复杂度）
- 所属项目
- 优先级（必填，默认 P2）
- 创建人 / 创建时间
- 当前状态 / 最近更新时间

### 4.2 优先级（三级，带选用说明）

| 级别 | 名称 | 何时选用 | 举例 |
|------|------|----------|------|
| **P1** | 严重 / 阻断 | 核心流程不可用、崩溃、错误结果、数据风险 | 无法登录；支付失败；数据丢失；闪退 |
| **P2** | 功能异常 | 能进入功能但行为不对、不稳定；有变通但仍影响使用 | 筛选错误；偶发提交失败；按钮无响应 |
| **P3** | 体验优化 | 不阻挡使用，偏 UI/文案/交互 | 间距、文案、动效、非阻塞改进 |

创建表单中每级展示一行辅助说明。管理员 / 管理员级 Key 可修改优先级。列表支持按优先级筛选。

### 4.3 附件

- **类型**：图片、视频、文档（pdf/docx/xlsx/txt/zip 等）、音频
- **交互**：选择文件 / 拖拽 / 剪贴板粘贴图片
- **录音**：在报障或补充说明中点击「录音」→ 浏览器调用系统麦克风 → 结束后保存为音频附件；可与图片等一并提交（如图 + 语音说明）
- **限制**：单文件 ≤ 50MB；单条报障附件数 ≤ 20；MIME/扩展名白名单
- **存储**：服务器本地目录；下载需登录且具备项目权限
- **挂载点**：可挂在 bug 本身，或某次状态变更（修复说明 / 不属实原因 / 打回说明）

## 5. 项目汇总

每个项目提供汇总视图：

1. **卡片**：报障总数；各状态数量（待处理 / 修复中 / 待确认 / 已确认 / 不属实）
2. **趋势图**：可选时间窗 7 / 30 / 90 天  
   - 每日**新建**数量  
   - 每日各状态**流入**次数（依据状态历史时间戳统计进入该状态的事件数）
3. 所有用于汇总的数据均来自带时间戳的创建记录与 `BugStatusEvent`

## 7. 数据模型（逻辑）

- **User**：username, passwordHash, role(`user`|`admin`), active, createdAt, updatedAt
- **Project**：name, slug, description, createdAt, updatedAt
- **ProjectMember**：projectId, userId
- **Bug**：projectId, title, body, priority(`p1`|`p2`|`p3`), status, reporterType(`user`|`api_key`), reporterId, createdAt, updatedAt  
  - 「原报障人」= `(reporterType, reporterId)`。用户网页创建 → `user` + userId；某 API Key 创建 → `api_key` + apiKeyId。确认/打回/异议只校验当前身份是否与该二元组一致（管理员不能冒充他人确认）。
- **BugStatusEvent**：bugId, fromStatus, toStatus, actorType(`user`|`api_key`), actorId, note, createdAt
- **Attachment**：ownerType(`bug`|`status_event`), ownerId, filename, mime, size, storagePath, createdAt
- **ApiKey**：name, keyHash, role(`user`|`admin`), createdByUserId, lastUsedAt, revokedAt, createdAt
- **ApiKeyProject**：apiKeyId, projectId（仅 `role=user` 的 Key 需要）

## 8. API 与 MCP

### 8.1 认证

- Web：Session Cookie（HttpOnly）
- Agent：`Authorization: Bearer <api_key>`
- 密码使用强哈希（argon2 或 bcrypt）

### 8.2 REST（UI 与 MCP 共用）

- Auth / Setup：`POST /api/setup`，`POST /api/auth/login`，`POST /api/auth/logout`，`GET /api/me`
- Users（管理员）：CRUD 风格的创建/列表/启用禁用
- Projects：CRUD；成员分配
- Bugs：创建/列表/详情/更新优先级；附件上传下载
- `POST /api/bugs/:id/transitions`：目标状态 + note + 可选附件（服务端校验权限与必填）
- `GET /api/projects/:id/stats`：总数、分状态、趋势序列
- ApiKeys（管理员）：创建（返回一次明文）、列表、吊销

权限：用户级身份只能访问所属项目；管理员级可访问全部。管理员级 Key / 管理员账号具备用户级全部接口能力。

### 8.3 MCP 工具（最小集）

| 工具 | 用户级 Key | 管理员级 Key |
|------|:----------:|:------------:|
| `list_projects` | ✓（仅所属） | ✓ |
| `get_project_stats` | ✓ | ✓ |
| `list_bugs` | ✓ | ✓ |
| `get_bug` | ✓ | ✓ |
| `create_bug` | ✓ | ✓（含用户级能力） |
| `confirm_fix` / `reject_fix` / `dispute_invalid` | ✓（仅该 Key 自己提的单） | ✓（同样仅当该 Key 是该单 reporter；管理员身份不能代他人确认） |
| `start_fix` | | ✓ |
| `submit_fix` | | ✓ |
| `mark_invalid` | | ✓ |

文档中提供两份 Cursor MCP 配置示例：`agent-qa`（用户级 Key）、`agent-fixer`（管理员级 Key）。

大附件：工具返回可下载链接或元数据，避免把大视频塞进模型上下文。

## 9. 技术与部署

- **栈**：Next.js（全栈）+ SQLite + 本地 uploads 目录
- **MCP**：同仓；独立进程或脚本调用同一业务逻辑 / HTTP API
- **Docker**：本仓库单服务容器；卷挂载 `data/db`、`data/uploads`；默认监听内网端口（如 `3000`），应用之间 / Agent 可直连内网地址
- **公网入口（可选）**：不强制依赖 nginx。需要暴露公网时，在独立仓库 `Apps/nginx` 增加 upstream + server 反代与 TLS；本服务仍只跑在内网
- **环境变量**：`BASE_URL`（内网或公网对外 URL，按实际访问入口配置）、`SESSION_SECRET`、上传路径、单文件大小等

### 安全（一期）

- 全站鉴权；项目级授权
- 上传白名单 + 大小限制；不执行用户文件
- 状态机服务端强校验
- API Key 可吊销；操作可审计
