# 分派失败信息更详细

日期：2026-11-16  
状态：已实现

## 问题

本机叫醒失败时，详情页「分派去修理」只显示类似：

`最近一次：… · 失败。HTTP 500 没有配置该项目的本地目录`

缺项目缩写、缺怎么修；管理员只能猜要改 `wake.config.json`。

## 目标

失败（及跳过）信息同时提供：

1. **人话**：说清原因和怎么修  
2. **原始 detail**：保留 `HTTP 500 …` 等技术原文，便于对照叫醒日志

成功态文案不变。

## 方案

双端补强（方案 A）：

### 1. `scripts/wake-agent.mjs`

工作目录相关错误带上项目缩写（有则写入）：

| 场景 | 新 `error` 文案（示例缩写 EMH） |
|------|----------------------------------|
| 未配置 / 空路径 | `没有配置项目 EMH 的本地目录（wake.config.json 的 projects）` |
| 路径不存在 | `项目 EMH 的工作目录不存在` |
| 不是文件夹 | `项目 EMH 的工作目录不是文件夹` |
| 主目录 / 根目录 | `项目 EMH 的工作目录不能是用户主目录或磁盘根目录` |
| 目录内有 wake.config.json | `项目 EMH 的工作目录里有叫醒密钥，请改到专用的项目目录` |

无可用缩写时，回退为现有不含缩写的短句（或「该项目」），不因缺 code 再失败一次。

`assertWorkdir` 可改为接收可选 `projectCode`，由 `/wake` 在解析 `configured` 失败时传入。

`agent_dispatches.detail` 仍经现有 `httpFailureDetail` → `HTTP ${status} ${error}`，再经 `redact` 截断；新文案须落在 180 字内。

### 2. `src/components/AgentDispatch.tsx` 的 `explainDetail`

对失败 / 跳过的 `detail`：

- 先匹配已知模式，产出**人话**（可含从原文解析出的项目缩写）
- 展示时：**人话。原始：{detail}**（若人话已等于原文则只显示一层，避免重复）

至少覆盖：

| detail 特征 | 人话要点 |
|-------------|----------|
| 未配置…本地目录 / projects | 在本机 `wake.config.json` 的 `projects` 里为该缩写写绝对路径，保存后重启叫醒服务 |
| 工作目录不存在 / 不是文件夹 | 检查该缩写对应路径是否存在且为目录 |
| 主目录或磁盘根目录 | 改成项目代码仓目录，不要用家目录或磁盘根 |
| 工作目录里有叫醒密钥 | 工作区不要放 `wake.config.json`，改到项目仓路径 |
| `fetch failed` / 连接类 | 保持现有「连不上…」说明，并附原始 detail |
| `没有可启动的本机 agent` | 保持现有说明，并附原始 detail |
| 其它 | 无法映射时只显示原始 detail |

同一套 `explainDetail` / `resultText` 用于：

- 报障详情 `WakeBugButton`「最近一次」
- 管理后台分派列表里失败/跳过的说明

### 3. 非目标

- 不改成功（`sent`）展示  
- 不改库表结构  
- 不回填历史失败行的 wake 原文（旧行靠 UI 映射尽量变好人话；无缩写时人话用「该项目」）  
- 不在本任务改 `wakeBugNow` 对 `fixing` 的限制

## 验收

1. 故意去掉 `projects.EMH` 后手动分派：detail 含 `EMH` 与 `wake.config.json` / `projects`；详情页同时出现人话与 `HTTP 500 …`。  
2. 叫醒未启动：人话仍为连不上说明，并带原始 `fetch failed`（或等价）。  
3. 现有 wake-agent 单测覆盖新错误文案；若有 UI/文案单测则补一条映射用例，没有则不强行加页面测试。  
4. 成功分派展示与改前一致。
